# Going public on GitHub

The repo is private at github.com/korkje/stubs.tv. The license is already
FSL-1.1-Apache-2.0 (ADR-0005) and the README pitches "fair-source and
self-hostable", so going public was always the plan — this doc is the
checklist for doing it safely. Delete it once the flip is done.

Flipping visibility exposes **everything at once**: the working tree, the
full git history of every branch, and all PRs/issues with their bodies and
comments. There is no partial flip, so anything that must not be public has
to be fixed *before* the switch.

## Audit findings (2026-08-19)

- **No secrets in the tree or anywhere in history.** `.env` files were never
  committed (only `.env.example`, which contains no values); a pattern scan
  of the full history (token prefixes, JWTs, service keys, bearer tokens)
  found only documentation *naming* secrets. `.npmrc` reads `MOTION_TOKEN`
  from the environment and never stores it.
- **The Motion+ dependency breaks public installs** — see blocking item 1.
- **POLAR_SETUP.md names live Polar resources** — see blocking items 2–3.
- CI has no `pull_request_target`, so fork PRs run without secrets; deploys
  are gated on pushes to main plus the `DEPLOY_ENABLED` repo variable.
  Nothing in the workflow leaks to forks.

## Decisions

### 1. AI docs (AGENTS.md, CLAUDE.md): keep them public — recommended

The instinct to separate them out (private submodule, gitignored files) runs
into a hard constraint from AGENTS.md itself: the owner works from multiple
agent environments, including cloud ones that clone **only this repo**. A
private submodule needs separate credentials in every environment; gitignored
local files aren't cloned at all. Both break the "documentation is
load-bearing" workflow that is the whole point of these files. On top of
that, `apps/web/AGENTS.md` is regenerated by `next dev`, so it cannot be kept
out of the tree.

AGENTS.md in a public repo is normal practice now, and for a fair-source
project it is genuinely useful contributor documentation — the README already
links it. So: keep the files, and instead do a **content review pass** —
read AGENTS.md, POLAR_SETUP.md, VISION.md, ROADMAP.md and PRIVACY.md once
with public eyes and move anything owner-private (there is little; pricing
and monetization are already public on the site).

Fallback, only if that review turns up real problems: slim the public
AGENTS.md down to contributor-relevant content and keep private notes in a
separate private repo. Not a submodule — nothing should make cloning or CI
depend on private credentials.

### 2. Git history: keep it — recommended

The history contains ~115 `Co-Authored-By: Claude` trailers, ~37 commit
subjects mentioning agents/AI, and merged `claude/*` branches. That is
cosmetic, not sensitive, and the secret scan came back clean. Rewriting
history is destructive (every SHA changes, ADR/PR cross-references break)
and pointless anyway: the PR history — including "Generated with Claude
Code" bodies — becomes public with the repo and cannot be rewritten at all.

If zero AI traces were genuinely required, the only honest option would be a
fresh repo squashed to a single initial commit, losing all history. Not
recommended; the transparency fits the project.

Cheap cleanup that *is* worth doing: delete the merged `claude/*` remote
branches (`git push origin --delete claude/...`) so the branch list is tidy.

### 3. Polar/billing: code stays public; ops docs move private — DECIDED

Decided with the owner 2026-08-19, after considering removing all
Polar-related code and both submodule directions (private submodule in the
public repo; private wrapper repo with the public repo as a submodule).

Why removal and submodules were rejected:

- **There is no application boundary to split on.** Sentry and Supabase keep
  their *product* (billing code included) public and their *SaaS control
  plane* — a separate application — private. FSL is Sentry's own license,
  written precisely so commercial product code can stay in the public repo.
  stubs.tv's billing is three files inside the one Next.js app (checkout
  route, webhook route, `lib/polar.ts`); a submodule seam through the middle
  of an app means either unfetchable clones (private submodule) or a
  permanent two-repo tax on every change (private wrapper as the real
  deploy source).
- **History exposes the integration regardless** (Decision 2), and the code
  is inert without secrets — `getPolarClient()` throws unless
  `POLAR_ACCESS_TOKEN`/`POLAR_SERVER` are set. The license, not file
  absence, is what stops competing commercial use.
- The genuinely private material is **operational, not code**: resource
  IDs, setup records, dashboard links.

What was decided:

1. **Billing code stays in this repo** under FSL.
2. **A private ops/notes repo** (e.g. `stubs.tv-private` — plain repo, no
   submodule linkage in either direction) takes POLAR_SETUP.md and any
   future operational records. `git rm` it here; history keeps the old
   copies, which is accepted and why archiving the named Polar test
   resources (see Blocking) matters.
3. **A self-hosted mode**, so the paywall disappears without Polar config:
   today a fresh instance starts everyone read-only (`plan = 'free'`,
   ADR-0014) and the operator must comp accounts by hand. A
   `SELF_HOSTED=true` (or "no Polar config") mode grants signups full
   access and hides the plans/pricing UI — a small change in `lib/plan.ts`
   plus the plans page. Gets its own ADR when implemented.

## Blocking — do before the flip

1. **Fix the Motion+ install wall.** `@motionplus/core` installs from
   `api.motion.dev`, which returns 400 without a paid `MOTION_TOKEN`
   (verified 2026-08-19). A fresh clone cannot `npm install`, which
   contradicts ground rule 4 (self-hosting) and the README's "Running
   locally" section, and fork PRs will fail CI at `npm ci` on any
   `package-lock.json` change (forks get no secrets). Owner's call
   (2026-08-19): make it optional or replace it. Candidates:
   - **replace `@motionplus/core`** (used for AnimateNumber) with
     [NumberFlow](https://number-flow.barvian.me) (`@number-flow/react`,
     MIT) — purpose-built animated numbers, no license wall. Cleanest;
     preferred unless something else comes to depend on Motion+. Drop the
     `@motionplus` entries from `.npmrc` and the `MOTION_TOKEN` secret from
     CI in the same change;
   - or make it optional (investigate `optionalDependencies` plus a dynamic
     import fallback — needs a spike: npm's env-var registry auth fails hard
     when the variable is unset, so the `.npmrc` entry itself is the wall,
     not just the dependency). More moving parts than the swap is worth if
     AnimateNumber is the only use.
2. ~~Confirm the Polar access token was rotated.~~ **Done** — owner
   confirmed rotation (2026-08-19). Fix the stale "must be rotated" note
   when POLAR_SETUP.md lands in the private repo (next item).
3. **Create the private ops repo and move POLAR_SETUP.md into it**
   (Decision 3): plain private repo, `git rm` the file here, no
   cross-repo linkage.
4. **Archive the Polar Test Product and the STUBSTEST discount.**
   POLAR_SETUP.md names a 100%-off discount code and its id. It is
   restricted to the (no-op) Test Product, but both are live resources
   named in this repo's git history, which moving the file (item 3) does
   not erase. The real fix is on Polar's side: archive both in the
   dashboard (already a checklist item there).
5. **Implement the self-hosted mode** (Decision 3), so the public repo's
   self-hosting story works without Polar from day one; write the ADR with
   it.
6. **Content review pass** over the docs listed under Decision 1.
7. **Run a security review of the code** (`/security-review` or equivalent)
   with emphasis on RLS policies, the admin routes, and the webhook/cron
   endpoints. Public source makes any gap discoverable by reading, not
   probing.

## Flip day

- Delete merged `claude/*` remote branches.
- Before flipping, in repo settings:
  - Branches: protect `main` — require the CI checks, no force pushes.
  - Actions: default workflow permissions read-only; keep "require approval
    for first-time contributors" (the default for public repos).
- Add `SECURITY.md` (how to report a vulnerability privately) and a short
  `CONTRIBUTING.md` (or a README section) covering local setup and the FSL
  license implications for contributions.
- Flip visibility to public.
- Immediately after flipping (these are free/public-repo features, not
  available while private on the free plan): enable secret scanning **and
  push protection**, and Dependabot alerts.

## After

  (it will, once blocking item 1 is fixed).
- Actions minutes become free for public repos; nothing to do, just noted.
- README: re-read as a stranger; the "Running locally" path must work
  end-to-end on a fresh clone.
